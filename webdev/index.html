What this demo is, and how it goes into fabricationtables.com

This site is a static copy of the current fabricationtables.com home page, rebranded to Gorilla Tables, with our table designer added as the product configurator. It exists to show what we want the live site to do. Everything here runs with no server, so you can read every file in the repository.

The three pieces

PieceWhat it isWhere it is here
The enginePlain JavaScript, no dependencies. Give it a design (an object of settings) and it returns the three prices, steel weight, rated load, parts and warnings in about 30 ms. The same code also produces the laser files, drawings and PDFs in the full app.assets/js/engine.js (79 KB, 31 KB gzipped)
The quick quoteThe "Build yours" section of the home page. Plain HTML and CSS in the site's own .gft style, plus site.js, which calls the engine in a Web Worker so the page never waits.index.html and assets/js/site.js
The designerThe full app: 3D preview, every option, hover help, assembly plan. One self-contained HTML file (design/app.html), served as is: no sign-in, no server. It sits in an iframe inside the site's own pages with ?embed=1, which drops its brand bar and takes the site's fonts and colours.design/index.html

How a design is described

A design is a flat object of settings in inches. The quick quote builds one from its buttons, the designer reads one from the address bar, and the cart line item should carry one so the shop can rebuild the exact table. The defaults are a 48 x 72, 1/4" plate, 6" deep, bolt-on legs on casters, raw steel.

{ "Table_L": 72, "Table_W": 48, "Top_Thick": 0.25, "Legs": "bolt", "Feet": "caster",
  "Tool_Pan": false, "Stand_Color": "Raw steel" }

// every key the designer knows works the same way, for example:
// Mat_Thick (frame plate), Hole_Dia / Hole_Pitch, Rib_Spacing, Table_H (depth), Work_H (working height),
// Legs: bolt | hframe | kd | none    Feet: caster | levcaster | leveler    Stand_Color: a RAL name or "Custom" + Stand_Custom

Open the designer with a design in the address and it loads it: design/?Table_L=96&Table_W=48&Legs=kd&Tool_Pan=true&tier=parts. tier is files, parts or built.

Pricing in the browser

<script src="assets/js/engine.js"></script>
<script>
  const E = GorillaEngine;
  const design = Object.assign(E.defaults(), { Table_L: 72, Table_W: 48, Legs: 'kd' }, E.casterPatch('caster'));
  const r = E.compute(design, E.DEFAULT_SHOP);
  // r.price.tiers -> [{ key:'files', name:'Files only', price: 66 }, { key:'parts', ... }, { key:'built', ... }]
  // r.totals.lb (steel weight), r.rating.lb (rated load), r.warnings, r.err (null when the design is buildable)
</script>

E.DEFAULT_SHOP holds every rate the price comes from: steel $/lb, scrap, laser $/hr, labour, casters, powder, crate, markups, the file-set floor. On the live site those numbers come from the WordPress admin page, not from the file.

What the live site needs that the demo doesn't have

  1. Prices worked out on the server. The browser can show a live price, but the price that goes on the order must come from the server, from the same engine with the shop's rates from the database. A small Node service runs engine.js unchanged: POST /quote with a design, get the tiers back.
  2. Add to cart. One WooCommerce product, "Custom fixture table", with the design JSON, tier, and server price on the line item. The demo's Add to cart buttons log the same object to the console and, inside the designer, post a gorilla-tables:add-to-cart message to the parent page.
  3. Files after payment. For "Files only", the order hook asks the engine service for the job files (POST /files) and gives the customer an expiring download link. The laser files are never made in the browser on the live site.
  4. Request a quote. The demo opens an email with the design pasted in. On the live site, the existing Gravity Forms quote form with the design JSON in a hidden field.
  5. Freight at checkout. The engine gives the weight; the LTL plugin quotes from it.
The full plan, with the database tables, admin page, freight, Google sign-in and the phases, is the "Gorilla Tables Website Plan" document Dave has. This page is the short version.

Embedding the designer

The designer is one HTML file. On this demo it is embedded twice: in the home page's "The table designer" section and full-screen at /design/, both as an iframe inside a normal site page with the site header above it. A design can be passed in the address:

<iframe src="/design/app.html?embed=1&Table_L=96&Table_W=48&Legs=kd" style="width:100%;height:calc(100vh - 104px);border:0"></iframe>

It is built from the private source repository with node tools/build.mjs --customer. The customer build is the short version: five steps (Size, Plate, Legs and stand, Finish, Review and order), no etch step and nothing etched for now, and none of the fine-detail groups the shop uses. It has no shop settings, no cost sheet, and none of the file-writing code at all (no DXF, PDF or zip): a customer designs, sees the price and orders; the shop produces the files after the order is approved. The shop keeps its own build with all of that.

Speed

  • Pricing a table: about 30 ms. The quick quote prices your build and every alternative on the option buttons (about 25 tables) in the background on each click.
  • The designer: 1.5 MB in one file (fonts and the 3D viewer inside), draws a table in under 100 ms, and keeps the last design on the device.
  • The home page: this HTML, one CSS file, two scripts and five images. No jQuery, no theme scripts.
