Notes for the web developer

This site is a working example of what we want fabricationtables.com to become: the same look and feel it has now, as a small set of pages, with the Gorilla Tables designer built in as a tool. Everything on it is static HTML, CSS and one script, so it drops into the existing WordPress theme page by page.

All of them are generated from one Python script, tools/build_site.py, so the header, footer and metadata are identical everywhere. You don't need the script; each page's HTML is complete on its own.

The designer

One self-contained HTML file, design/app.html (about 1 MB; fonts, 3D viewer and pricing all inside). Serve it as is: no sign-in, no server, no build step. It sits in an iframe inside a normal page with ?embed=1, which drops its own brand bar and takes the site's fonts and colours:

<iframe src="/design/app.html?embed=1" style="width:100%;height:calc(100vh - 104px);border:0"></iframe>
<iframe src="/design/app.html?embed=1&tab=standard" ...>                       the Standard tables tab
<iframe src="/design/app.html?embed=1&Table_L=96&Table_W=48&Legs=kd&tier=parts" ...>   a preloaded design

The customer version is the short one: five steps (Size, Plate, Legs and stand, Finish, Review and order), no etching, none of the shop's fine-detail groups. It has no shop settings, no cost sheet and none of the file-writing code (no DXF, PDF or zip), so there is nothing to download from it: a customer designs, sees the price and orders, and the shop produces the files after the order is approved. The shop keeps its own full build.

How a design is described

A design is a flat object of settings in inches. The designer reads one from the address and writes one into the cart message and the quote email:

{ "Table_L": 72, "Table_W": 48, "Top_Thick": 0.25, "Legs": "bolt", "Feet": "caster",
  "Tool_Pan": false, "Stand_Color": "Raw steel", ... }

Keep it with the order exactly as given: the shop rebuilds the table from it, and the same object opens in the shop's own copy of the designer for the laser files and the paperwork.

Cart and quote

When a customer presses Add to cart, the designer posts a message to the page it sits in:

window.addEventListener('message', e => {
  if (!e.data || e.data.type !== 'gorilla-tables:add-to-cart') return;
  const o = e.data.order;   // { tier: 'built' | 'parts' | 'files', price, size, config, rated_lb, weight_lb }
  // add a WooCommerce line item: name = `${o.size} fixture table, ${o.tierName}`, price = o.price, meta = JSON.stringify(o.config)
});

Request a quote opens an email to sales@fabricationtables.com with the design attached. Swap it for a form post if you prefer.

Prices

The designer prices from the 2026 price list (the same figures as the tables page): standard sizes at the list, custom sizes interpolated between them by area, the list's own adders for 3/8" top, tool pan, no legs, welding and powder, and the cost model only for options the list doesn't name. The price in the browser is what the customer sees; the price that goes on the order should be checked on the server from the design object (same rules, or simply the shop confirming the order before payment is taken).

What the live site needs that this demo doesn't have

  • Checkout. The cart message above into WooCommerce, with freight (LTL by ZIP) and liftgate as options.
  • Order approval. Files-only orders are delivered after the shop approves the order (the designer never writes files on the customer's side).
  • The contact form posting to the shop instead of opening an email.
  • Photos. The hero and product photos are the current site's; more of real Gorilla tables would help.

Speed

  • Every page is static: HTML, one CSS file, one small script, fonts from Google. No framework, no build.
  • The designer is one file, loaded once; computing a table takes about 30 ms, the assembly pictures under a second.
  • Images are JPEGs sized for the page and lazy-loaded below the fold.
